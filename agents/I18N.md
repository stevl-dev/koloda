# Internationalization (i18n)

- **Message ID naming**: dot-separated `kebab-case` segments (e.g., `settings.hotkeys.ui.focus-next`);
  never camelCase or PascalCase.
- **Placeholders**: interpolate a plain identifier (`${stepNumber}`), not an expression (`${i + 1}`, `${a.b}`).
  Lingui names the placeholder after it; an expression extracts as a positional `{0}`, which `check:i18n` rejects.
- **Catalogs**: each lib with user-visible strings keeps its own `libs/<name>/locales/<locale>/messages.po`.
  The root `lingui.config.ts` lists those lib catalogs.
  Each app config extends it and adds its own `apps/<app>/locales` catalog.
  A new lib with strings needs an entry in the root config.
  It also needs one in `apps/design-system/src/app/i18n.ts`, which imports the lib catalogs by hand.
  Keep that list in the root config's order.
- **Extract messages (web)**: `nx run @koloda/web:lingui-extract --clean`
- **Compile messages (web)**: `nx run @koloda/web:lingui-compile`
- **Extract messages (desktop)**: `nx run @koloda/electron-react:lingui-extract --clean`
- **Compile messages (desktop)**: `nx run @koloda/electron-react:lingui-compile`
- Either app's extract updates the lib catalogs too.
  Compile merges lib and app catalogs into that app's `src/app/locales`.
- **Translation workflow**: Extract → Add translations to .po files → Compile
- **Check**: `bun run check:i18n` (part of `check:push`) runs extract and compile for both apps.
  It fails when a catalog or compiled file changes, so commit what the workflow produced.
